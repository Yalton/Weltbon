# Security policy

## Reporting a vulnerability

Please do not open a public issue for a suspected vulnerability or include exploit details, credentials, customer data, or production configuration in a discussion.

Use GitHub's **Report a vulnerability** form in the Security tab of the Weltbon repository. If private vulnerability reporting is temporarily unavailable, contact a repository owner privately and ask for a secure reporting channel without sending sensitive details in the first message.

Include the affected version or commit, deployment mode (web, self-hosted, or desktop), reproduction steps, impact, and any suggested mitigation. Maintainers will acknowledge receipt, coordinate validation and remediation, and agree on disclosure timing with the reporter. No response-time guarantee is offered until a formal support policy is published.

## Scope

Reports about the public API, web client, desktop app, sync protocol, import/export behavior, release artifacts, and self-hosted deployment belong here. Vulnerabilities specific to Citreum's hosted infrastructure, billing, customer data, or private operator systems belong in a private report to the relevant operator.

Supported versions will be listed in release notes once public versioned releases begin. Until then, fixes target the latest `master` revision and the most recent release where practical.
